# Scraping-for-Saitama-City-Document

指定したURL配下の全ページを巡回し、ページ内のダウンロード可能な資料を収集して、
1つのPDFに結合するツールです。結合結果が30MBを超える場合は資料単位を保ったまま
分割し、デスクトップの新規フォルダに出力します。

- [要件定義書](docs/requirements.md)
- [設計書](docs/design.md)

## 準備

### 1. Python

Python 3.10 以上をインストールしてください。インストール時に
**「Add python.exe to PATH」にチェックを入れてください。**

### 2. LibreOffice

PDF以外の資料（Word / Excel / PowerPoint など）をPDFに変換するために必要です。

https://ja.libreoffice.org/ からインストールしたあと、`soffice.exe` のあるフォルダ
（既定では `C:\Program Files\LibreOffice\program`）を環境変数 PATH に追加してください。

### 3. ライブラリ

コマンドプロンプトでこのフォルダに移動し、次を実行します。

```
pip install -r requirements.txt
```

## 使い方

```
python main.py
```

実行するとURLの入力を求められます。URLを入力すると、その配下の全ページを巡回して
資料を収集します。

```
対象URLを入力してください: https://example.com/docs/
```

処理はサーバーに負荷をかけないよう **1リクエストあたり3秒間隔** で進みます。
資料が多いサイトでは数時間かかる場合があります。中断したいときは `Ctrl+C` を
押してください。クロール中であれば、そこまでに集めた資料で処理を続けるかを選べます。

### 初めてのサイトを対象にするとき

いきなり全体を実行すると、対象によっては数時間かかります。まず下見と小規模な
試験実行で、収集範囲が想定どおりかを確かめてください。

```
# 1. 下見 — ページを巡回して収集対象の一覧だけを出す（ダウンロードはしない）
python main.py https://example.com/docs/ --dry-run --max-pages 20

# 2. 小規模な本番実行 — 20ページ分だけ実際に収集してPDFまで作る
python main.py https://example.com/docs/ --max-pages 20

# 3. 本番実行
python main.py https://example.com/docs/
```

| オプション | 内容 |
|---|---|
| `url` | 対象URL。省略すると実行後に入力を求めます |
| `--dry-run` | 下見。クロールのみ行い、収集対象の一覧を `manifest.csv` に書き出します |
| `--max-pages N` | 巡回するページ数の上限 |
| `--cabinet 名前` | DiscussCabinet専用。対象キャビネットを指定します |

`--dry-run` はLibreOfficeが無くても実行できます。

### さいたま市議会 DiscussCabinet について

`https://www.discusscabinet.net/saitama/list` は通常のWebサイトと構造が異なり、
資料への `<a href>` リンクが存在しません。画面遷移が全て「隠しフィールドを
書き換えてのフォームPOST」で行われるためです。

このURLを入力した場合は**専用のクローラに自動で切り替わります**。利用者の操作は
他のサイトと同じで、URLを入れるだけです。

```
python main.py https://www.discusscabinet.net/saitama/list --dry-run
```

実行すると対象キャビネットの選択を求められます。

```
キャビネットを選択してください（全体を対象にすると長時間かかります）:
   0) すべて
   1) 本会議
   2) 委員会
   3) マニュアル
選択 (0-3, 既定 0):
```

`--cabinet 本会議` のように指定すれば、この選択をとばせます。

**このサイトは1文書につき2リクエスト**（詳細画面とファイル本体）を要します。
本会議・委員会は年度ごとに大量の文書があるため、**必ず `--dry-run` で件数と
所要時間を確認してから**本番実行してください。年度単位に絞りたい場合も、
まず下見で全体像を把握することを勧めます。

## 出力

デスクトップに `さいたま市文書_YYYYMMDD_HHMMSS` という新規フォルダが作られます。

```
さいたま市文書_20260821_170500\
├─ 結合資料_001.pdf       結合された資料（30MB以内）
├─ 結合資料_002.pdf
├─ log.txt                処理の時系列ログ
├─ manifest.csv           資料一覧（どの資料が何ページ目に入ったかの対応表）
└─ _未収録ファイル\        変換・展開に失敗して結合できなかった資料（無ければ作られません）
```

結合資料PDFに取り込まれた元ファイルは内容が重複するため残りません。
どの資料が結合資料PDFのどこに入ったかは `manifest.csv` で確認できます。

## 仕様の要点

| 項目 | 内容 |
|---|---|
| 巡回範囲 | 入力URLのパス配下、かつ同一ホストのページのみ |
| 資料の収集範囲 | 同一ホストであればパス配下でなくても収集する（`/docs/` のページから `/files/` のPDFを参照する構成に対応） |
| 対象形式 | PDF / Word / Excel / PowerPoint / txt / csv / 画像 / zip |
| 画像 | `<a href>` でリンクされたものだけを収集。`<img src>` の表示用画像（ロゴ等）は対象外 |
| zip | 展開して中の資料も対象にする（入れ子は5階層まで） |
| 重複排除 | 同一URL、および内容が同一（SHA-256一致）の資料を除外 |
| robots.txt | 遵守する。`Crawl-delay` の指定が3秒より長ければそちらに従う |
| 認証ページ | 対象外 |
| 分割 | 全出力ファイルを30MB以内に収める。1資料が単体で30MBを超える場合のみページ単位で分割 |

## テスト

本番はWindows向けですが、開発時の確認はmacOS / Linuxでも行えます。

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

.venv/bin/python -m unittest discover -s tests      # 自動テスト（40件）
.venv/bin/python tests/demo_local.py                # ツール本体を通しで実行
```

`demo_local.py` はローカルにテスト用サイトを立てて `main.py` を最初から最後まで
実行します。実サイトにはアクセスせず、出力も一時フォルダに作られるため
デスクトップは汚れません。

- `--desktop` … 出力先を実際のデスクトップにする
- `--interval 3` … 本番と同じ3秒間隔で実行する

LibreOfficeが無い環境では変換をスタブで代替します。実際の変換品質まで確認したい
場合は `brew install --cask libreoffice` でインストールしてください。

## 制約

- JavaScriptで動的に生成されるリンクは収集できません（静的HTMLのみを解析します）。
  対象サイトのページソースを開き、資料へのリンクが `<a href>` として存在することを
  事前に確認してください。
- 処理中は元ファイル・変換後PDF・結合結果が一時的に共存するため、
  総資料サイズの約3倍の空き容量が必要です。
- robots.txtは遵守しますが、サイトの利用規約による制約は判定できません。
  実行前にご確認ください。
