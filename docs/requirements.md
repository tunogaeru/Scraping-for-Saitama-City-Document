# 要件定義書
## さいたま市文書スクレイピング・PDF統合ツール

- 作成日: 2026-08-21
- バージョン: 0.1（ドラフト）

---

## 1. 目的

指定したWebサイトのURL配下にある全ページを巡回し、ページ内に存在するダウンロード可能な資料（PDFを主とし、それ以外の形式も含む）を収集する。収集した資料をすべてPDF形式に変換したうえで1つのPDFに結合し、ファイルサイズが30MBを超える場合は資料単位を保ったまま複数ファイルに分割する。最終成果物はデスクトップ上に新規作成したフォルダにまとめて格納する。

## 2. 動作環境

| 項目 | 内容 |
|---|---|
| OS | Windows |
| 実行方法 | コマンドプロンプト（cmd.exe）上で `python main.py` のように実行 |
| 言語 | Python 3.x |
| 追加ソフトウェア | LibreOffice（`soffice` コマンドをPATHに登録しておく。Office系ファイルのPDF変換に使用） |
| ネットワーク | インターネット接続必須（対象サイトへのアクセス） |

## 3. 全体処理フロー

```
1. プログラム起動
2. コマンドプロンプト上でURLの入力を求める
3. 入力されたURL配下のページをクロールし、全ページのURL一覧を収集する
4. 収集した各ページ内から、ダウンロード可能な資料へのリンクを抽出する
5. 抽出した資料を順次ダウンロードする（重複は除外）
6. ダウンロードした資料のうちPDF以外の形式をPDFに変換する
7. 変換後、全てのPDFを1つのPDFファイルに結合する
8. 結合後のファイルサイズが30MBを超える場合、資料単位の境界を保ったまま複数ファイルに分割する
9. デスクトップに新規フォルダを作成し、最終的なPDFファイル群を格納する
10. コマンドプロンプト上に完了メッセージを表示して処理を終了する
```

## 4. 機能要件

### 4.1 URL入力

- プログラム実行直後、標準入力でURLの入力を求める（例: `対象URLを入力してください: `）。
- 入力値が正しいURL形式（`http://` または `https://` で始まる）でない場合は再入力を促す。

### 4.2 クロール範囲

- 入力されたURLの**パス配下のみ**を対象とする。
  - 例: `https://example.com/docs/` を入力した場合、`https://example.com/docs/2024/report.html` は対象、`https://example.com/other/` は対象外。
- 同一ドメイン・同一パスプレフィックス配下のHTMLページのみを辿る。外部ドメインおよび対象パス外へのリンクは辿らない。
- クロール階層数・取得ページ数の上限は設けない（無制限）。ただし訪問済みURLを記録し、循環参照・重複アクセスを防止する。
- リクエストは逐次実行とし、**1リクエストごとに1.5秒のウェイト**を入れる（対象サーバーへの負荷軽減のため）。
- robots.txt を遵守する。実行開始時に対象ドメインの robots.txt を取得し、Disallow 指定されたURLはクロール・ダウンロードの対象外とする。
- ログイン等の認証が必要なページは対象外とする（認証処理は実装しない）。認証が必要でアクセスできなかったページはログに記録する。

### 4.3 資料の抽出・ダウンロード

- 各ページのHTMLを解析し、`<a>` タグ等のリンク先が資料ファイルと判定できるものを抽出する。
- 資料と判定する拡張子:
  - PDF: `.pdf`
  - Office文書: `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt`, `.pptx`
  - 画像: `.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.tif`, `.tiff`
  - その他: `.txt`, `.csv`, `.zip`
- 画像ファイルは資料として扱い、ダウンロードおよびPDF変換の対象に含める。
  - ただし、サイトのデザイン用画像（ロゴ、アイコン、ボタン等）まで収集すると成果物が汚れるため、`<a href>` のリンク先として明示的にダウンロード提供されている画像のみを対象とし、`<img src>` で表示されているだけの画像は対象外とする。
- 同一ファイル（同一URL）は重複ダウンロードしない。
- ダウンロードしたファイルは、後段の処理・検証のためそのまま保持する（元ファイル保持については4.6参照）。
- ダウンロード失敗（404、タイムアウト等）はエラーログに記録し、処理は継続する。

#### zipファイルの扱い

- `.zip` はダウンロード後に展開し、**中に含まれる資料も収集対象に含める**。
- 展開したファイルのうち、4.3の対象拡張子に該当するものを通常の資料と同様にPDF変換・結合の対象とする。
- zip内にさらにzipが含まれる場合も再帰的に展開する（無限再帰を防ぐため展開階層に上限を設ける。例: 5階層）。
- 展開に失敗した場合（パスワード保護、破損等）はエラーログに記録し、当該zipは結合対象から除外して処理を継続する。
- 展開先は作業用サブフォルダ内とし、元のzipファイルと展開後ファイルの双方を保持する。

### 4.4 PDF変換

- PDF以外の形式でダウンロードした資料は、LibreOffice CLI（`soffice --headless --convert-to pdf`）を用いてPDFに変換する。
  - 対象: Office文書（`.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt`, `.pptx`）、テキスト（`.txt`, `.csv`）、画像（`.jpg` 等）。
- LibreOffice は利用者が事前にインストールしておくことを前提とする。プログラム起動時に `soffice` コマンドの存在をチェックし、見つからない場合はその旨をコマンドプロンプトに表示して処理を中止する。
- 変換に失敗したファイルはエラーログに記録し、結合対象から除外する（処理全体は継続する）。
- `.zip` 自体はPDF化せず、展開後の中身を変換対象とする（4.3参照）。

### 4.5 PDF結合・分割

- 変換済みPDFと元からPDFだった資料をすべて1つのPDFに結合する。
- 結合順序はクロールで発見した順（ページ順・ページ内リンク順）とする。
- 結合後のファイルサイズが30MBを超える場合、**資料単位の境界を維持したまま**複数ファイルに分割する（1つの資料の途中でファイルを分割しない）。
- **出力する全てのファイルは30MB以内に収める**（30MB = 30 × 1024 × 1024 バイト）。
  - 1件の資料単体で30MBを超える場合に限り、その資料をページ単位で分割し、各ファイルが30MB以内になるようにする。この場合も他の資料とは結合せず、当該資料単独で複数ファイルに分かれる。
  - 例外: 1ページ単体で30MBを超える資料（高解像度スキャン等）はそれ以上分割できないため、30MB超過を許容し、警告としてログに記録する。
- 分割ファイルの命名規則: `結合資料_001.pdf`, `結合資料_002.pdf`, ...（連番）。分割が発生せず1ファイルのみの場合も `結合資料_001.pdf` とする。

### 4.6 出力・後片付け

- デスクトップ直下に新規フォルダを作成する（フォルダ名例: `さいたま市文書_YYYYMMDD_HHMMSS`）。
- 作成したフォルダ内に、分割後のPDFファイル群を格納する。
- **結合資料PDFと内容が重複するファイルは最終フォルダに残さない。** 具体的には以下のとおり。
  - ダウンロードした元ファイル、zip展開後のファイル、PDF変換後の中間ファイルのうち、結合資料PDFに取り込まれたものは削除する。
  - 一方、**結合資料PDFに取り込まれなかったファイルは削除せず残す**（内容が重複しないため）。該当するのは以下のようなケース。
    - PDF変換に失敗した資料
    - 展開に失敗したzipファイル（パスワード保護・破損等）
    - 結合処理に失敗した資料
  - 残したファイルは作業用サブフォルダ（例: `_未収録ファイル`）にまとめ、ログから対応が追えるようにする。
- 中間ファイルはデスクトップの出力フォルダではなく一時作業ディレクトリで扱い、処理完了時に上記ルールに従って必要なもののみ出力フォルダへ移動する方式とする。

### 4.7 完了通知

- 全処理完了後、コマンドプロンプト上に完了メッセージを表示し、プログラムを終了する。
- 完了メッセージには以下のサマリーを含める。
  - 出力先フォルダのパス
  - クロールしたページ数
  - ダウンロード成功件数 / 失敗件数
  - PDF変換成功件数 / 失敗件数
  - 出力した結合PDFのファイル数
  - 失敗があった場合はログファイルの参照を促すメッセージ

### 4.8 サイト別対応

対象サイトのうち `https://www.discusscabinet.net/saitama/list`（さいたま市議会 文書管理システム DiscussCabinet）は、資料への `<a href>` リンクを持たず、画面遷移が全てフォームPOSTで行われるため、4.2〜4.3の方式では収集できない。

- このホストのURLが入力された場合は**専用のクローラに自動的に切り替える**。利用者の操作は他サイトと変わらない（URLを入力するだけ）。
- 専用クローラが担当するのは資料の発見とダウンロードまでとし、PDF変換以降（4.4〜4.7）は共通処理を用いる。
- 文書量が多いため、対象キャビネット（本会議／委員会／マニュアル）を選択できるようにする。
- 詳細は[設計書 11.5節](./design.md)を参照。

### 4.9 下見モード

初めて対象にするサイトで、いきなり全件のダウンロードを始めると数時間を要し、対象サーバーにも負荷がかかる。事前確認のためのモードを設ける。

- クロールのみを行い、ダウンロード・変換・結合は行わない。
- 収集対象の一覧を `manifest.csv` として出力し、収集範囲が想定どおりかを確認できるようにする。
- 本番実行の予想所要時間を表示する。
- PDF変換を行わないため、LibreOffice が未導入でも実行できる。
- あわせて、巡回ページ数の上限を指定できるようにする（小規模な試験実行のため）。

ドラフト時点で未確定だった項目の確定内容。

| No. | 項目 | 決定内容 | 該当節 |

| 2 | 画像ファイルの扱い | 資料に含める。ただし `<a href>` でリンクされた画像のみを対象とし、`<img src>` の表示用画像は対象外 | 4.3 |

| 4 | リクエスト間隔・並列数 | 逐次実行、1リクエストごとに1.5秒ウェイト | 4.2 |
| 5 | robots.txt の遵守 | 遵守する。Disallow対象はクロール・ダウンロードしない | 4.2 |
| 6 | 認証が必要なページ | 対象外（認証処理は実装しない）。アクセス不可のページはログに記録 | 4.2 |
| 7 | 実行途中のエラー | ログに記録して処理を継続。最終サマリーに成功/失敗件数を表示 | 4.7, 6 |
| 8 | LibreOfficeの導入 | 利用者が事前にインストール。起動時に存在チェックし、未導入なら処理を中止 | 2, 4.4 |
| 9 | 中間ファイルの扱い | 結合資料PDFと内容が重複するもの（元ファイル・変換済みPDF）は出力フォルダに残さない。結合に含まれなかったファイルのみ `_未収録ファイル` に残す | 4.6, 7 |

## 6. 非機能要件

- 処理中は進捗状況（クロール件数、ダウンロード件数、変換件数など）をコマンドプロンプト上に随時表示する。
- ネットワークエラー・タイムアウト発生時は一定回数リトライしたうえでスキップし、処理全体を止めない。
- 処理対象サイトに過度な負荷をかけないよう、リクエスト間隔を設ける。
- ログファイル（成功/失敗一覧）を出力先フォルダ内に保存する。

## 7. 出力ディレクトリ構成（例）

```
デスクトップ\
└─ さいたま市文書_20260821_153000\
   ├─ 結合資料_001.pdf
   ├─ 結合資料_002.pdf
   ├─ log.txt
   └─ _未収録ファイル\
       └─ （PDF変換・zip展開・結合に失敗し、結合資料PDFに含まれなかった資料のみ）
```

※ 結合資料PDFに取り込まれた元ファイル・変換済みPDFは内容が重複するため出力フォルダに残さない。
　 `_未収録ファイル` は該当ファイルが1件もない場合、フォルダ自体を作成しない。

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| 配下ページ | 入力URLのパスをプレフィックスとして持つ、同一ドメイン内のページ |
| 資料 | ページ内リンクからダウンロード可能なファイル（PDF、Office文書等） |
| 結合資料PDF | 全資料をPDF化・結合した最終成果物（30MB制限により複数ファイルに分割される場合がある） |
